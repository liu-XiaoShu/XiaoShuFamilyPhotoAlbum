## 1. 背景与目标

### 1.1 背景

相册分散在多目录，缺少统一时间组织与可随文件迁移的说明信息。需要一套**本机/局域网**工具：把照片与视频整理进约定目录，在页面上浏览、修订、下载，并可安全分享给家人。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| 统一归档 | 按「年 / 月 / 详细时间-简述-内容指纹」结构入库 |
| 元数据伴随 | 时间、简述、描述、地点写入文件元数据（及侧车） |
| 可纠错 | 入库前自动解析后可改；入库后可编辑 |
| 流畅浏览 | 时光 / 经典 / 地图；搜索；大纲 + 按月分页 |
| 可控权限 | 超级用户；分享二维码按范围授权 |
| 存储可感知 | 磁盘水位、重复项可处理、原文件可下载 |
| 轻量局域网 | 单机服务，不做公网社交 |

### 1.3 非目标

- 公网多租户、云同步、评论互动  
- 专业 RAW 暗房 / AI 自动标签  
- 依赖独立商业图库账号

## 3. 总体架构

```
浏览器（局域网）
  登录 / 浏览（时光·经典·地图·搜索）/ 管理 / 存储 / 设置 / 访问数据 / 关于
        │ HTTPS
FastAPI（run.py / Docker）
  鉴权 · 入库队列 · 去重 · 下载 · 缩略图 · 地图 · 访客 · 分享 · 存储统计
        │
album/  年/月/规范文件  +  .trash/ 回收站
data/   auth · visitors · thumbs · map_pack · geo · brand · certs
inbox/  待入库
```

**原则：** 文件系统 = 媒资真相；SQLite 索引可重建；用户确认后才入库落盘。

## 4. 目录与命名

```
album/2026/2026-09/2026-09-21-162600-杭州游玩-ea0730b7.jpg
album/.trash/<id>/…          # 回收站条目
```

冲突时追加 `-2`、`-3`…，从不静默覆盖。旁白/封面/Live/侧车随主文件改名。

索引表可存完整 `content_hash`（32 位 MD5）用于去重；文件名仍用前 8 位。

## 5. 功能清单（v2.0.0 已实现）

### 5.1 登录与权限

- 未登录 → `/login`；匿名媒资拒绝（已建超管后）  
- 登录页**不预填**用户名  
- 分享：`/?share=token`；可见 = 授权范围 ∪ 该访客自己入库  
- 回收站列表/恢复对分享访客做可见性校验  

### 5.2 浏览与管理

- 时光 / 经典 / 地图；**搜索**（折叠展开）  
- 入库：自动解析、上传队列、内容去重、HEIC/实况  
- 看图：灯箱、实况、**下载原文件**、编辑、自动播放  
- **存储**页（超管）：占用 + 重复项检查/处理  
- 回收站、设置、访问数据、关于（展示 v2.0.0 与定版日期）  

### 5.3 编辑与下载

- 图片旋转裁剪；视频剪辑与封面；旁白录音  
- `GET /api/download?path=` 附件方式下载（中文文件名 RFC 5987）  

### 5.4 地图

- `map_provider`: `auto` | `amap` | `offline`  
- 高德：服务端拉取 + 缓存；坐标 WGS84→GCJ-02  

### 5.5 运维

- `scripts/pi/*`；Docker 国内源；`HOST_UID/GID`  
- 健康检查返回 `version` + `released_at`
