# 小树时光相册 · Docker 部署与使用说明

> 适用版本：**v3.0.0**（更新时间 2026-10-05）

本文说明在 Linux 服务器（含树莓派 Ubuntu）上用 Docker 部署、启动、查状态，以及重置超级用户密码的方法。

本地开发仍可用：

```bash
python3 run.py          # 默认 HTTPS
python3 run.py --http   # 明文 HTTP（仅调试）
```

## 1. 环境要求

- Docker + docker-compose（Ubuntu 可用：`sudo apt install docker.io docker-compose`）
- 当前用户在 `docker` 组，或命令前加 `sudo`
- 开放端口 **8765**（局域网访问）

本仓库已配置国内加速：

| 用途 | 源 |
|------|-----|
| 基础镜像 | DaoCloud（`docker.m.daocloud.io`） |
| 容器内 apt | 清华 Debian |
| pip | 清华 PyPI |

建议在宿主机配置 Docker 镜像加速（`/etc/docker/daemon.json`），例如：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://mirror.ccs.tencentyun.com"
  ]
}
```

修改后执行：`sudo systemctl restart docker`

## 2. 部署流程

### 2.1 准备目录

```bash
mkdir -p ~/xiaoshu-album
# 把本仓库文件同步到该目录（含 Dockerfile、docker-compose.yml、app/ 等）
cd ~/xiaoshu-album

cp -n config.example.json config.json
mkdir -p album inbox data/thumbs data/brand data/map_pack data/geo data/certs
```

`config.json` 中常用项：

```json
{
  "album_root": "album",
  "import_root": "inbox",
  "thumb_root": "data/thumbs",
  "host": "0.0.0.0",
  "port": 8765,
  "album_title": "小树时光相册",
  "map_provider": "offline"
}
```

地图底图：`map_provider` 可为 `auto` / `amap` / `offline`。

以后外接硬盘可把 `album_root` 改成绝对路径，并在 `docker-compose.yml` 里增加对应 volume 挂载。

### 2.2 docker-compose 要点（v2）

仓库里的 `docker-compose.yml` 与 `docker-compose.pi.yml` 默认把相册 / 待入库 / data 挂到同一块数据盘（示例 `/mnt/album-data`），入库可 `rename`，避免从 SD 卡拷到硬盘打满 IO。部署时把路径和 `HOST_UID`/`HOST_GID` 改成你机器上的实际值。

其它机器若只用仓库目录，可改成相对路径：

```yaml
version: "3.3"
services:
  album:
    build: .
    image: xiaoshu-album:latest
    container_name: xiaoshu-album
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./album:/app/album
      - ./inbox:/app/inbox
      - ./data:/app/data
      - ./config.json:/app/config.json
    environment:
      - TZ=Asia/Shanghai
      - HOST_UID=1000          # 宿主机运行相册的用户 uid
      - HOST_GID=1000
```

树莓派 USB 盘示例（与本仓库 `docker-compose.yml` 相同思路）：

```yaml
volumes:
  - /mnt/album-data:/mnt/album-data
  - /mnt/album-data/data:/app/data
  - /mnt/album-data/inbox:/app/inbox
  - ./config.json:/app/config.json
command: ["python", "run.py", "--https"]
```

`config.json` 里 `album_root` / `import_root` / `thumb_root` 应指向盘上真实路径（容器内能访问到的路径）。

说明：

- **默认 HTTPS**：镜像 `CMD ["python", "run.py"]`，证书在 `data/certs/`。  
- **不要**在 compose 里写 `command: ["python", "run.py", "--http"]`，除非明确只要 HTTP。  
- `HOST_UID` / `HOST_GID`：容器内以 root 写盘时，会尽量把新文件 chown 到宿主机用户，便于备份排查。部署后建议执行一次：  
  `sudo chown -R "$(id -un):$(id -gn)" album inbox data`（或 USB 盘上的对应目录）  
- `.dockerignore` 应忽略整个 `data/`（或至少 `data/certs`），避免构建上下文读不到 root 私钥而失败。
- **相册与 inbox 必须同盘**，否则入库会变成跨设备拷贝，树莓派上极易卡死。

### 2.3 构建并启动

```bash
cd ~/xiaoshu-album
chmod +x scripts/pi/*.sh

./scripts/pi/deploy.sh     # 一键构建并启动
# 等价：sudo docker-compose up -d --build
```

| 脚本 | 作用 |
|------|------|
| `./scripts/pi/start.sh` | 启动（已有镜像） |
| `./scripts/pi/stop.sh` | 停止 |
| `./scripts/pi/restart.sh` | 重启 |
| `./scripts/pi/debug.sh` | 状态 + 日志 + 健康检查 |
| `./scripts/pi/xiaoshu-ctl.sh` | 全部子命令入口 |

### 2.4 验证

| 入口 | 地址 |
|------|------|
| 登录 | `https://<服务器IP>:8765/login` |
| 首页 | `https://<服务器IP>:8765/` |

```bash
./scripts/pi/debug.sh
curl -sk https://127.0.0.1:8765/api/health
# 期望含 "version":"3.0.0","released_at":"2026-10-05"
```

**重要：** 打开登录页后立刻创建超级用户。详见 [安全说明.md](./安全说明.md)。

**注意：** `config.json` 必须是**文件**。若误变成空目录，删掉后从 `config.example.json` 复制重建。

更新代码后：

```bash
sudo docker-compose build
sudo docker-compose up -d --force-recreate
```

## 3. 日常启动 / 停止 / 重启

```bash
cd ~/xiaoshu-album
./scripts/pi/start.sh
./scripts/pi/stop.sh
./scripts/pi/restart.sh

# 或
sudo docker-compose up -d
sudo docker-compose stop
sudo docker-compose restart
sudo docker-compose up -d --build   # 改代码后
```

容器配置了 `restart: unless-stopped`，机器重启后一般会自动拉起。

## 4. 查看状态

```bash
./scripts/pi/debug.sh
sudo docker-compose ps
sudo docker-compose logs --tail=100
sudo docker stats xiaoshu-album --no-stream
```

| `State` | 含义 |
|---------|------|
| `Up` | 正常运行 |
| `Exit` / `Exited` | 已退出，看 logs |
| `Restarting` | 反复崩溃，看日志 |

## 5. 重置超级用户密码

```bash
cd ~/xiaoshu-album
sudo docker-compose exec album python run.py --reset-admin-password
# 可选改用户名：
sudo docker-compose exec album python run.py --reset-admin-password --admin-user 新用户名
```

重置后打开：`https://<服务器IP>:8765/login`

## 6. 数据与目录说明

| 宿主机路径 | 用途 |
|------------|------|
| `album/` | 相册媒资 |
| `album/.trash/` | **回收站**暂存（按条目子目录） |
| `inbox/` | 待入库 |
| `data/thumbs/` | 缩略图缓存 |
| `data/auth.sqlite` | 超管与分享会话 |
| `data/visitors.sqlite` | 访客与入库统计 |
| `data/geo/places.sqlite` | 地点 → GPS（勿提交到 Git） |
| `data/map_pack/` | 离线地图包（体积可能较大） |
| `data/certs/` | HTTPS 自签证书 |
| `config.json` | 运行配置 |

备份建议至少包含：`album/`（含 `.trash` 若需保留回收站）、`data/auth.sqlite`、`config.json`，以及需要的 `data/map_pack/`、`data/geo/`。这些是本机数据，**不要推到公开 GitHub**。

## 7. 常用排障

**打不开网页 / HTTPS 证书警告**

```bash
sudo docker-compose ps
sudo docker-compose logs --tail=50
ss -tlnp | grep 8765
# 自签证书：浏览器点继续；手机 Safari 勿误拦 Cookie
openssl x509 -in data/certs/localhost.pem -noout -dates -subject
```

**构建失败：Permission denied … localhost-key.pem**

`.dockerignore` 未排除 `data/certs`。加入 `data` 后重新 `docker-compose build`。

**手机登录成功但像未登录**

常见原因：自签 HTTPS + Safari 存不住 `Secure` Cookie。确认一直用 **HTTPS** 同一主机名/IP；避免无痕与 Cookie 拦截；勿混用 HTTP/HTTPS。

**改了 `config.json` 不生效**

```bash
sudo docker-compose restart
```
